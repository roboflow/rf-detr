!!! info "How the latency numbers were obtained"

    - **Latency**: the end-to-end `RFDETRInference.predict` call (preprocessing, forward pass and postprocessing) at batch 1, timed once for each of 500 distinct COCO val2017 images after 20 warm-up calls, with the [latency cookbook](../../../cookbooks/measure-latency/). The columns are the configurations the cookbook tries on Apple Silicon: PyTorch with inductor in FP32 and FP16, PyTorch with TorchScript in FP16, and CoreML in FP32 and FP16 with two sets of compute units. PyTorch TorchScript is the traced model that `model.inference()` builds with `compile_backend="torchscript"`. CoreML uses the default `device="auto"`, which lets Core ML plan work on the Neural Engine, and CoreML GPU loads the same package with `device="cpu_and_gpu"`. No INT8 configuration is measured on Apple Silicon, because the Core ML export has no INT8 option.
    - **Run**: Apple M4 Max (16-core CPU, 40-core GPU), macOS 26.7.1, rfdetr 1.13.0.dev0, rfdetr_plus 1.2.0, torch 2.14.0 and coremltools 9.0, measured on 2026-11-13. Every column and every size comes from one run of the cookbook, and no other work was started on the machine while it ran. PyTorch inductor predictors are built by `model.inference()`, which holds Dynamo's recompile limit above the default of 8 and compiles with `dynamic=False`; without that, inductor predictors built after the eighth in one process run several times slower or fail to compile, as the [FAQ](../../../faq/#why-is-an-inductor-predictor-slower-after-i-built-several-models-in-one-process) explains.
    - **Ties**: repeated runs of the largest models differed by 5 to 7%, so treat a gap under about 5% to the next configuration as a tie and pick by accuracy and tooling.

!!! warning "FP16 can lower accuracy"

    Most of the fastest configurations above run in FP16. The FP16 AP in the [table above](#pre-trained-checkpoints) was scored on TensorRT FP16 engines, where it stays within 0.1 AP of FP32 for every size here. It was not scored for PyTorch or CoreML FP16 on Apple Silicon, so check the accuracy on your own data before you rely on an FP16 configuration.
